# Monitoring: Prometheus + Grafana

CareQueue's backend exposes Prometheus metrics at `GET /metrics` (port 8000, not
routed by the Ingress). The cluster runs **kube-prometheus-stack** (Prometheus
Operator, Prometheus, Alertmanager, Grafana, kube-state-metrics, node-exporter)
in the `monitoring` namespace. The CareQueue chart adds the scrape config and the
alerts as Kubernetes objects next to the app.

| File | What it is |
|------|------------|
| `kube-prometheus-stack-values.yaml` | Lean values for a laptop kind cluster: 6 h retention, small requests, Grafana limit 512Mi (256Mi was OOMKilled), the `*SelectorNilUsesHelmValues: false` settings so Prometheus picks up ServiceMonitors/rules from every namespace, and the kind-unreachable control-plane targets turned off. |
| `grafana-dashboard-carequeue.json` | The "CareQueue - Clinic API" dashboard (uid `carequeue`), 15 panels. |
| `../helm/carequeue/templates/servicemonitor.yaml` | ServiceMonitor `carequeue-backend`: scrape `/metrics` on the Service port `http` every 15 s. |
| `../helm/carequeue/templates/prometheusrule.yaml` | PrometheusRule `carequeue-alerts` (the alert rules, below). |

Both chart objects are rendered only if the `monitoring.coreos.com/v1` CRDs are
installed, so the chart still installs on a cluster without monitoring (CI).

## Install

```bash
# 1. kube-prometheus-stack + the dashboard ConfigMap
scripts/monitoring-up.sh
#    = helm upgrade --install kps kube-prometheus-stack \
#        --repo https://prometheus-community.github.io/helm-charts --version 92.9.0 \
#        -n monitoring --create-namespace -f monitoring/kube-prometheus-stack-values.yaml --wait
#    + kubectl create configmap carequeue-grafana-dashboard --from-file=carequeue.json=monitoring/grafana-dashboard-carequeue.json
#      labelled grafana_dashboard=1 (the Grafana sidecar loads it into the "CareQueue" folder)

# 2. (re)deploy CareQueue so the ServiceMonitor and PrometheusRule exist
scripts/deploy-local.sh
kubectl get servicemonitor,prometheusrule -n carequeue
```

## Open Prometheus and Grafana

```bash
kubectl -n monitoring port-forward svc/kps-prometheus 19090:9090   # http://localhost:19090
kubectl -n monitoring port-forward svc/kps-grafana    13001:80     # http://localhost:13001  (user: admin)

# Grafana admin password: generated by the chart, stored only in the cluster
kubectl -n monitoring get secret kps-grafana -o jsonpath='{.data.admin-password}' | base64 -d; echo
```

- Prometheus → **Status → Target health**, search `carequeue`:
  `serviceMonitor/carequeue/carequeue-backend/0`, one target per backend pod, all `UP`.
- Grafana → Dashboards → CareQueue → **CareQueue - Clinic API**.
- Generate traffic so the panels move:
  `BASE_URL=http://localhost:8088/api HOST_HEADER=carequeue.local DURATION=180 CONCURRENCY=24 scripts/load-test.sh`

## Metrics

| Metric | Type | From |
|--------|------|------|
| `http_requests_total{handler,method,status}` | counter | prometheus-fastapi-instrumentator |
| `http_request_duration_seconds_bucket{handler,method,le}` | histogram | instrumentator |
| `carequeue_appointments_booked_total` | counter | booking endpoint |
| `carequeue_appointments_status_total{status}` | counter | status changes |
| `carequeue_queue_waiting{doctor}` | gauge | checked-in patients waiting today |
| `container_cpu_usage_seconds_total`, `container_memory_working_set_bytes` | | kubelet/cAdvisor |
| `kube_horizontalpodautoscaler_status_{current,desired}_replicas` | | kube-state-metrics |

Each backend pod runs one Uvicorn worker and has its own counters; the
dashboard always `sum`s (or `max`es, for the queue gauge) across pods. Counters
restart from 0 with a pod, which `rate()`/`increase()` handle.

## Dashboard panels

Stats: backend targets up, requests/s, 5xx error %, p95 latency, appointments
booked, backend replicas. Time series: request rate by handler, p95 latency by
handler, responses by status code, 5xx/4xx error rate, appointments booked and
status changes per 5 min, queue waiting by doctor (bar gauge), pod CPU, pod
memory, HPA current/desired/max replicas. Variables: data source, namespace,
backend service.

## Alerts (`carequeue-alerts`)

| Alert | Expression (simplified) | For | Severity |
|-------|-------------------------|-----|----------|
| `CareQueueBackendDown` | `(sum(up{service="carequeue-backend"}) or vector(0)) == 0` | 2m | critical |
| `CareQueueHigh5xxRate` | 5xx share of requests over 5 min > 5% | 5m | warning |
| `CareQueueQueueTooLong` | `max by (doctor) (carequeue_queue_waiting) > 10` | 10m | warning |

Thresholds are chart values (`monitoring.prometheusRule.errorRatePercent`,
`queueWaitingMax`). See them in Prometheus → Alerts, or
`curl -s localhost:19090/api/v1/rules | jq '.data.groups[] | select(.name=="carequeue.rules")'`.
